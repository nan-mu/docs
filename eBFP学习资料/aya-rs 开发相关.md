# `aya-rs` 开发相关

`aya-rs`是目前`rust`唯一的开发框架，本文会讲解一些使用`aya`开发的相关概念和介绍一些资料

`eBPF`是目前云原生领域被选择的监控技术。特点是运行在内核空间。他本质上是编译器编译出一段特殊的汇编，在`linux`内核中有一个能在特定条件下触发的运行时虚拟机去执行这段汇编，在后文中我们将之称为内核态（the kernel side）。另一个特殊的点是在`rust`视角下，这个运行时汇编是一个`no_std`环境，且无法开辟一个栈空间使用一些`alloc`的结构。某种意义上后端的动态变量由`linux`托管，暴露给`rust`编译器的是一个已经经过初始化的一个一个动态变量。像`aya-rs`这样的`eBPF`开发框架会提供一个命令行工具能够帮你自动在`linux`中注册你所使用的动态变量。由`linux`托管的原因是不仅仅有内核态的程序需要读取这些变量，在用户态的一些程序也需要。这里提到的用户态的程序在`aya`中可以被视为内核态程序的守护进程，内核态程序以及其所需要交互的变量这两者的生命周期由它管理。所以为了方便后文会称呼它为用户态（user side）。

`eBPF`的另一个特点是快，原因是内核态的运行时虚拟机被设计为尽快收敛的类型。以网络为例，有文章称eBPF可以负担10G以上的流量。代价则是功能十分有限。大部分在应用层面的工作由用户态负责。所以内核态的设计思路就是设计一个过滤器，它能接触到非常底层的信息，要做的只是将之有用的部分放到动态变量中去。

用户态则与`aya`强相关，这里我想先介绍一下`aya`到底是什么东西。毫无疑问它能够帮助我们开发一套完整的`eBPF`程序，但它是如何实现的？我在社区中提了这个问题，我认为我的猜想得到了肯定的答复：https://discord.com/channels/855676609003651072/855676609003651075/1288889587179065448。

大概是这样，在内核态，程序由LLVM生成，类似于C语言中的libelf和内核代码中的辅助函数。Aya-rs绕过了这一层，直接通过LLVM生成eBPF程序。换句话说，它处理了某些辅助函数的实现和ELF的翻译。

在用户态，`aya-rs`与大多数C库一样，基于syscall来执行诸如与映射交互和与内核空间通信等操作（目前我还没深入了解加载之外的内容，但我使用的工具对我的程序运行得很好）。与其处于同一层次的还有libbpf，两者都使用bpf()系统调用。

我认为这是比较关键的，因为目前技术还比较新，文档不是很全，用户态的很多内容我们需要找到它的实现才能找到它的文档。 

另外我还想提到一点，之前说过`aya-rs`的用户态被设计为内核态的守护进程，它能使用`std`，能连接数据库或者发送网络请求。和我们工作相关的更重要的一点是，它并不需要内核态程序一定由`rust`编写，他也能向`linux`注册复数个内核态程序。我认为在和数据库段使用`rust`能够很大程度上带来更好的效率。在内核态的话，说实话我还没有进行更加深入的研究。
